# W5.1b — the soft-leakage ablation: profiling from dirty data

Route W5.1b of `docs/research_program.md` §11, reviewer **gap 4b**, and
the ablation `CLAUDE.md` §3 has named since day one. Generated by
`experiments/w5_leakage_ablation.py`. Seed 42, full datasets, mock repair
mode, shipped detector/cost defaults, 5 splits with bootstrap 95 % CIs.

## 0. What the two arms are

| arm | `DatasetProfile` built from | what that means |
|---|---|---|
| **clean** | `clean_df` | the shipped code path; reproduces every published number |
| **dirty** | `dirty_df` only | IQR fences, valid ranges, vocabularies, imputation medians/quartiles and column kinds all derived from corrupted data |

Mechanism: `profile_dataset(name, paths, dirty_df, dirty_df)` — the dirty
frame in both positions — installed for the dirty arm by rebinding the
name inside `src.pipeline.runner`. **No shipped file is edited.** Every
statistic Phase 3 and Phase 4 read comes from the frame passed in the
`clean_df` position, so all of them become dirty-derived.

The wrapper is verified, not trusted: `profile.n_corrupted_cells` and the
two missing-value counts are computed by comparing the two frames, so in
the dirty arm they must be 0 and equal. The script **aborts** if they are
not — a silently failed patch would show a reassuring zero gap.

Ground truth still enters the dirty arm exactly where it enters the clean
one (0/1 labels for `p` and `q`, and scoring). This ablation removes
*aggregate* clean knowledge, not the permitted label use.

## 4. Realised cost and the zero-regret claim

Two costings, both needed:

- **flagged-only** — the published metric. NOT comparable across arms:
  the arms flag different numbers of cells, so a lower flagged-only cost
  can mean a better policy or merely a smaller flag set.
- **total harm** (W5.1a mode) — flagged-only plus
  `C_abstain x undetected corruptions`. The denominator is the dataset's
  whole corruption, which is the same for both arms, so **this is the
  comparison that is actually like-for-like.**
