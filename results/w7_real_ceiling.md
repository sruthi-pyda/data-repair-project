# W7.1e — the ceiling for the corruption that is actually in the data

Generated by `experiments/w7_real_ceiling.py`. Seed 42.

`results/w7_ceiling.md` measured a ceiling of **0.2723** for
`swap_valid` at adult's prevalence and concluded a 6.4x improvement was
available. **That number is for frequency-weighted swap corruption, and
the real data is not that.** This file computes the ceiling for the
corruption actually present, using byte-identical oracle and posterior
code.

## 1. What the real corruption actually is

320 corrupted cells of 8,000 (rate 0.0400).

| clean -> dirty transition | count |
|---|---:|
| `1 -> 0` | 320 |

**Entirely one-directional.** Every corrupted cell was turned
into the same value, so a corrupted cell is indistinguishable
*marginally* from an ordinary cell holding that value.

Cells whose value the corruption could have produced: **2,266**, of which **0.1412** are genuinely corrupted. That share is
the hard cap on what marginal evidence alone can tell you — every
cell outside the support is provably clean, so all the uncertainty
is concentrated in that subset.

## 3. Why this is the number to quote

The synthetic grid answers "how much signal would exist if corruption
were frequency-weighted". This answers "how much exists in the table we
actually ship". Where the two disagree, **this one governs**, and the
earlier 6.4x figure must not be quoted for real adult.

Standing caveats, unchanged from `docs/w7_plan.md` §3.3: the ceiling is
an **estimate**, it depends on the oracle's `P_clean` (a weak oracle
understates it, so a captured fraction above 1.0 means the oracle lost
to the method rather than the method beating optimality), and the oracle
reads ground truth so it is **non-deployable by construction**.
