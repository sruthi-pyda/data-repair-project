# W9.1 — what would perfect column triage be worth?

Generated by `experiments/w9a_triage_value.py`. Planned in
`docs/w9_plan.md` §W9.1, committed before the code. Seed 42.

## 0. The question, and why the premise matters

**The pipeline already runs the detector on every column.** `Detector`
iterates every `profile.column_names` and there is no column-selection
gate anywhere in `src/pipeline/runner.py`, so adult's whole-table
PR-AUC of 0.0025 *is* the run-on-every-column number. Column triage was
never a pipeline stage; it was a diagnostic question about why running
everywhere fails.

Running everywhere does not fail from a selection error. It fails
because rare-but-clean cells in other columns **outrank** the corrupted
ones, so extra columns contribute false positives that displace true
positives from the top of the ranking. This table sizes that effect.

## 1. Oracle status — read before quoting anything here

Both oracle variants read `clean_df` to decide which columns are
corrupted. They are **non-deployable by construction**, the same
clearly-labelled diagnostic use as the `(ii)` AUC in W5.3 and the Bayes
ceiling in W7.1. The purpose is to size the prize, never to flag a cell.

- **masked** (primary) — score every cell, then zero the score on every
  genuinely clean column, evaluated over **all** cells. The cell
  universe and prevalence are unchanged, so it is directly comparable
  with the whole-table figure beside it.
- **restricted** (secondary) — evaluated only over cells in corrupted
  columns. **Prevalence changes**, so it is NOT comparable with the
  whole-table number and must not be quoted beside it without this note.

## 3. What this settles

Largest headroom under perfect triage (conditional detector):

- `adult`: **69.4x**
- `rayyan`: **1.7x**
- `beers`: **1.5x**
- `tax`: **1.4x**

The headroom is the prize that five separate mechanisms failed to
claim any of — M1 the likelihood ratio, W5.3 self-detectability, M2 the
contamination fraction, W8-A CACM and W8-D Excess Surprise. Each was
refuted with an identified cause, and `docs/w8_plan.md` §8 unifies them:
every per-column statistic absorbed a column-specific nuisance term
larger than the corruption signal, in a hierarchy — background density,
then cardinality, then model competence, then model error rate, then
model miscalibration.

So this table is the honest two-sided result for the paper: **the prize
is large, and it is not reachable by any statistic we could construct**
from the dirty table at these prevalences. That is a measured
limitation with a mechanism, not an absence of effort.
