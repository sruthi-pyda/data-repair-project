# W4.4 — difficulty-aware repair routing (mechanism M1)

Generated by `python experiments/w4_routing.py --live`. Dataset **breast_cancer**, full data, seed 42, top-k 3. Costs from `configs/costs.yaml`: wrong=50, human=5, abstain=10 (abstract penalty units, never monetary).

The detector flags **392** cells; every table below is over the **355** the policy acts on. The difference is the two ID-like columns (`Unnamed: 0`, `Sample code number`) that `src/pipeline/runner.py` excludes from every decision and every cost — so accuracy and cost here describe the same cells, and the accuracy is directly comparable with the 0.6732 in `docs/PROJECT_REPORT.md` §3.5.

> Model: `openai/gpt-oss-120b`. Cells already answered by the earlier Breast Cancer run are served from the on-disk cache, so this run is reproducible and nearly free.

## Verdict

- Best non-oracle router: **by_error_type** at 71.0% top-1 accuracy.
- Pure controls: `always_rule` 67.3%, `always_llm` 71.0%.
- **Routing did NOT beat both pure strategies.** The best control, `always_llm`, is at 71.0% vs 71.0% for the best router — a difference of +0.0 points. Reported as a loss, per CLAUDE.md §8b.8.
- Ceiling (`oracle`, upper bound only): 77.7%; headroom above the best router is 6.8 points.
- API calls: the best router makes 210 model calls vs 355 for `always_llm` — 145 saved (40.8%).
- Cheapest realised policy cost among deployable routers: `always_rule` at 1,615 experimental units.
